# 前端 UI 与交互

## 设计方向

使用 Naive UI，但主题明确偏蓝。整体应像组织内部事项系统，而不是营销页或生成式模板页。界面重点是读议题、看状态、投票、写意见、管理权限。

## Naive UI 主题

建议基色：

```ts
export const themeOverrides = {
  common: {
    primaryColor: '#1677ff',
    primaryColorHover: '#4096ff',
    primaryColorPressed: '#0958d9',
    primaryColorSuppl: '#1677ff',
    borderRadius: '6px',
    fontFamily: 'Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif'
  }
}
```

配色使用蓝色作为动作色，页面背景使用浅灰白，状态色使用 Naive UI 默认语义色，不要把所有组件都染成蓝色。

## 信息架构

### PC 布局

- 顶部栏：系统名、搜索、登录用户、管理入口。
- 左侧筛选区：状态、分类、可见范围、我的订阅。
- 主区域：议题列表或议题详情。
- 议题详情右侧栏：状态、分类、投票时间、可见组、投票组、订阅。

### 移动端布局

- 顶部栏压缩为标题 + 搜索图标 + 用户入口。
- 筛选使用 `NDrawer` 或底部弹层。
- 议题详情改为单列，投票面板置于正文后、评论前。
- 管理后台移动端只保证可操作，不追求与 PC 同等密度。

## 页面要求

### 议题列表

组件建议：

- `NInput` 搜索。
- `NSelect` 状态筛选。
- `NTag` 分类。
- `NDataTable` 用于 PC 管理视图。
- 普通用户列表用紧凑的自定义列表行，避免卡片堆叠。

每行显示：

- 标题和编号。
- 状态。
- 分类。
- 可见性。
- 评论数、投票数。
- 更新时间。

### 议题详情

页面结构：

- 标题区：编号、标题、状态、操作按钮。
- 正文区：Markdown 渲染。
- 投票面板：三选一，显示投票窗口和我的投票。
- 评论区：按时间线排列。
- 侧栏/折叠信息：分类、权限、创建者、时间、订阅。

投票按钮建议使用 `NRadioGroup` 或三枚等宽按钮：

- 同意
- 不同意
- 弃权

提交前如果允许改票，按钮文字为“提交投票”；已投票后显示“更新投票”。如果不能改票，投票后禁用并显示投票时间。

### 评论延时公开

- 用户提交后，如果 `publishAt` 在未来，评论在本人视角显示“待统一公布”。
- 其他普通用户不可见该评论。
- 管理员视角可见但要明显标注，不应和已公开评论混在一起误读。

### 管理后台

左侧导航：

- 概览
- 用户
- 权限组
- 议题
- 分类
- 系统设置
- 审计日志

管理页优先用 `NDataTable`、`NForm`、`NModal`、`NDrawer`。高风险操作使用确认弹窗。

## 组件约定

- 表单校验统一用 Naive UI `rules`。
- 时间选择统一用 `NDatePicker`，提交 UTC ISO 字符串。
- 权限组选择使用 `NSelect multiple`，显示组名称，提交 `groupKey`。
- 分类选择使用 `NSelect multiple` 或自定义分类选择器。
- Markdown 编辑 MVP 可以用普通 textarea + preview；后续可接入成熟 Markdown 编辑器。

## 响应式断点

- `< 640px`：移动端单列。
- `640px - 1024px`：平板，列表和详情仍单列，但侧栏折叠。
- `> 1024px`：PC 双栏。

## 避免的问题

- 不做大幅 hero、宣传语、渐变背景。
- 不用过圆的卡片堆满页面。
- 不用“AI 生成感”的空洞说明文案。
- 不把权限信息只藏在 tooltip 里，关键限制必须可读。
- 不在前端自行决定敏感数据是否可见，必须以后端返回为准。
